# 常见问题（FAQ）

> 适用范围：本仓库当前开发版（版本 0.1.7，开发阶段 4/7）。功能和接口仍可能调整；文中标注“计划中”的条目**尚未实现**，请以实际发布版本为准。
>
> 相关文档：[部署与运维指南](DEPLOYMENT.md) · [安全边界说明](SECURITY-NOTES.md) · [完整安全模型](../SECURITY.md) · [README](../README.md)

## 一、使用

### 1. 为什么没有删除按钮？到底该怎么删文件？

本工具只做“找出重复 + 生成待删清单”，**不提供删除、移动、改名或写入接口**，也不会调用系统删除命令。正确流程是：

1. 扫描并审核，每组至少保留 1 份；
2. 生成删除方案，工具会重新核对待删项和保留项的 size/mtime/SHA-256；
3. 清单状态为“已通过复核”（final）后导出 JSON/CSV/HTML；
4. 你本人在 NAS 文件管理器或命令行里，按清单手工核对并删除。

删除动作始终由人确认，工具只负责提供可核对的证据。审核列表按目录/扩展名筛选（计划中）会在后续版本补充。

### 2. 新建扫描方案后，为什么没有自动开始扫描？

扫描方案默认是**未启用**状态，需要先设置扫描时机并手动启用；也可以随时点“立即扫描”手动触发一次。调度器只自动运行已启用的方案，未启用的方案不会因为保存就开跑。

### 3. 到了计划时间，为什么扫描没有运行？

按以下顺序排查：

- 容器是否在运行：调度器只在容器运行期间工作，停机期间错过的任务**不会补跑**；
- 方案是否已启用，扫描时机是否配置正确；
- 容器时区 `TZ` 是否正确（例如 `Asia/Shanghai`），否则“02:00”会按 UTC 计算；
- 触发方式是否为“只提醒不扫描”（notify_only），该模式只发提醒，需要你手动点扫描；
- 是否已有扫描在运行：同一时间只允许一个扫描任务。

错过的任务请手动点“立即扫描”，或重新生成扫描计划。

### 4. “同名候选”和“内容重复”有什么区别？

- **内容重复**：文件大小相同，且完整 SHA-256 相同。首次扫描会先用抽样哈希快速筛候选，正式分组和删除方案复核都以完整哈希为准。
- **同名候选**：文件名（basename）相同，内容未必相同。若同组文件哈希一致，会额外标记“内容相同”，但仍需人工判断是不是同一文件的不同副本或不同版本。
- 0 字节文件不参与内容重复判定；符号链接、FIFO、设备文件不会跟随、也不会进入重复组。

**同名候选不能当作重复批量删除**，务必逐组确认内容。

### 5. 审核之后文件被修改或删除了，怎么办？

生成删除方案时，工具会逐项重新核对 size/mtime/SHA-256：

- 有文件变化 → 标记“已修改”，清单状态变为“未通过复核”，导出会被 409 拒绝；
- 有文件消失 → 标记“已不存在”，同样不能导出；
- 保留份缺失或被改写 → 整份清单拒绝导出，避免删掉最后一份。

处理方式：在审核组详情或清单页点“重新校验”；确认文件已稳定后，重新扫描、重新审核、重新生成方案。不要绕过复核直接手工删除。

### 6. 导出的 CSV 用 Excel 打开乱码，或路径前多了一个单引号？

- CSV 使用 **UTF-8 BOM** 编码，第一行是 `#` 开头的说明（本工具不执行删除），不是表头。请用 Excel 的“数据 → 从文本/CSV”并选择 UTF-8，或直接用文本编辑器打开。脚本处理时请跳过 `#` 开头的行。
- 为防止 Excel 公式注入，以 `=`、`+`、`-`、`@`、制表符或回车开头的单元格会被加上一个前导单引号。复制路径时请去掉这个引号，文件本身没有变化。

### 7. 误删了文件，工具能恢复吗？

**不能。** 工具不保存文件内容（索引只记录路径、大小、时间、哈希），也没有回收站或撤销功能。请尽快通过 NAS 回收站（如 `#recycle`）、文件系统快照或备份恢复，越早停止写入越好。导出的清单可以作为“原路径 + 大小 + SHA-256”的核对依据。

### 8. 硬链接会被当成重复文件吗？删掉一个会释放空间吗？

扫描按设备号 + inode 去重，同一份数据的多个硬链接只记录一条，因此**硬链接不会作为重复组出现**，也不会进入待删清单。多个硬链接共享同一份数据，删除其中一个路径不会释放空间，只有删除最后一个链接才会释放。

## 二、权限与安全

### 9. 为什么有些目录/文件在页面里看不到？

常见原因：

- 页面只展示已启用扫描根的**顶层**条目，不做逐层文件浏览；扫描方案也只能选根目录，不能选子目录；
- 想只扫某个子目录：把它单独以只读方式挂载成一个根，并在 `MOUNT_ROOTS` 中列出（需要重建容器）；
- 符号链接、FIFO、设备文件不跟随、不索引；
- 无读权限的文件会被跳过，并计入扫描错误统计；
- include/exclude 规则影响扫描与索引，不影响目录页的条目展示；
- 目录树接口最多返回 500 条，页面只展示其中一部分，并按目录优先排序。

目录树逐层下钻（返回 `has_children`/子路径）**计划中**，当前版本只能看单层。

### 10. 容器启动就退出，或提示权限/挂载错误，怎么办？

启动自检会拒绝以下情况（guard 失败，退出码 2）：

- `MOUNT_ROOTS` 为空；
- 扫描根在宿主机不存在、不是目录，或运行账号不可读；
- 扫描根**实际可写**：工具会做启动写探测，并向下抽样（深度 ≤3、最多 20 个子目录）；只要有一处能创建文件就拒绝启动。

另外，`./data` 不可写也会导致启动失败（通常是异常退出，不一定是退出码 2），请确认 `data` 属主与 `APP_UID`/`APP_GID` 一致。

排查：`docker compose logs dupe-checker` 看具体原因；确认 `.env` 里 `SCAN_ROOT` 是绝对路径；确认 compose 中挂载为 `${SCAN_ROOT}:${SCAN_ROOT}:ro`；确认 `APP_UID`/`APP_GID` 对目录有读 + 执行权限；在容器内用 `id` 和 `ls` 验证。

运行中如果挂载变成可写，工具会在定期复查时置为 unsafe，扫描、生成方案、导出都返回 409。修复挂载后等待下一次复查或重启容器。

### 11. `AUTH_MODE=none` 免登录安全吗？

只适合**完全可信的内网**。免登录时仍会签发 CSRF 会话；能访问端口的人可以查看清单、触发扫描、导出清单，但工具本身没有删除/写入执行能力。**不要**把端口映射到公网，也不要在公网反代后使用 `none`。默认请用 `password`。

### 12. 忘记口令，或想恢复口令登录？

把 `.env` 的 `AUTH_MODE` 改回 `password` 并重启容器：

- 之前设置过口令：访问 `/login` 登录；
- 从未设置过口令：访问 `/setup`，需要一次性初始化令牌（获取方式见 [DEPLOYMENT.md](DEPLOYMENT.md) 的“首次初始化”）。

当前版本**没有在线找回/重置口令**功能。已初始化但忘记口令时，只能从备份恢复 `./data`，或把 `./data` 移到别处后重新初始化（会丢失索引、审核记录和日志，但**不会影响 NAS 上的文件**）。

### 13. 工具会把文件内容或清单上传到云吗？

不会。工具没有遥测、没有云调用；扫描只读取文件元数据并计算哈希，不上传文件内容；数据库、导出文件、日志都保存在本地 `./data` 下。

## 三、运维

### 14. 扫描很慢或占用很高，怎么办？

- 首次全量扫描需要计算 SHA-256，最慢；之后未变化的文件会复用哈希缓存；
- 可以在扫描方案里设置元数据/哈希限速（`rate_meta`/`rate_hash`）和扫描时段（`window`），避开使用高峰；
- 扫描过程中可以暂停、继续或取消；
- 文件特别多时，建议先扫描一个较小的根验证配置，再逐步扩大范围。

### 15. 数据存在哪里？升级或重装会丢吗？

所有持久数据都在 `./data`：

- `data/db/dupe.db`：索引、审核记录、方案；
- `data/exports/`：导出的清单；
- `data/logs/`：运行日志；
- 可能还有首次初始化的 `setup_token`（仅初始化前存在）。

容器重建不会删除 `./data`；删除 `./data` 等于清空索引、审核记录和日志。升级前请先备份 `./data`，具体步骤、备份恢复和卸载见 [DEPLOYMENT.md](DEPLOYMENT.md)。
